2. 학습 시작 멘트

토끼의 증가, 나선 은하, 그리고 반복되는 관계

생명과학에서는 개체 수가 세대를 거치며 이전 상태의 영향을 받아 변합니다. 수학에서는 앞의 두 수를 더해 다음 수를 만드는 피보나치수열을 통해 이러한 관계를 표현합니다. 식물의 잎 배열, 솔방울의 나선, 조개껍데기의 성장 무늬에서도 비슷한 수적 패턴을 관찰할 수 있습니다.

천문학에서는 나선 은하의 팔 구조와 행성의 공전 궤도를 수학적 관계로 분석하고, 공학에서는 로봇의 움직임을 여러 단계의 작은 동작으로 분해합니다. 복잡한 목표를 직접 해결하기보다, 이미 해결 방법을 알고 있는 더 작은 목표로 바꾸는 것입니다.

오늘 학습할 피보나치수와 하노이 탑은 단순한 수학 놀이가 아닙니다. 하나의 문제가 여러 개의 작은 문제로 갈라질 때 어떤 계산이 생기는지, 그리고 그 관계를 어떻게 정확한 함수로 설계하는지를 보여 주는 대표 사례입니다.

4. 개념 및 상세 설명 · 관련 코드 · 코드별 확인 문제

개념 1. 재귀 함수 설계 절차

재귀 함수를 설계할 때는 먼저 문제를 같은 형태의 더 작은 문제로 바꿀 수 있는지 확인한다. 다음으로 더 이상 나눌 필요가 없는 가장 작은 문제를 종료 조건으로 정하고, 현재 문제와 작은 문제의 관계를 코드로 표현한다.

아래 함수는 자연수 n부터 1까지의 합을 n + sum_to(n-1)로 정의한다.

문제 축소종료 조건재귀 관계
def sum_to(n): if n == 0: return 0 return n + sum_to(n - 1) print(sum_to(5))

출력: 15

코드 1 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ③, ④
종료 조건에서 0을 반환하고, 각 단계에서 n을 더하며 n-1 문제로 줄어든다.
개념 2. 매개변수로 현재 상태 전달하기

재귀 함수의 매개변수는 현재 단계의 상태를 나타낸다. 문제 크기뿐 아니라 누적값, 시작 위치, 도착 위치와 같은 정보를 다음 호출에 전달할 수 있다.

아래 함수는 acc에 현재까지의 합을 저장하며 재귀 호출한다.

def sum_acc(n, acc): if n == 0: return acc return sum_acc(n - 1, acc + n) print(sum_acc(4, 0))

코드 2 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ②, ③, ⑤
첫 호출은 sum_acc(4, 0)이고, acc는 0→4→7→9→10으로 변한다.
개념 3. 전역 변수로 호출 횟수 기록하기

전역 변수는 여러 재귀 호출이 공통으로 참조하거나 변경할 값을 기록할 때 사용할 수 있다. 예를 들어 전체 호출 횟수를 세는 데 활용할 수 있다.

다만 전역 변수는 함수 밖의 상태를 바꾸므로 함수의 독립성을 낮출 수 있다. 학습용 측정에는 유용하지만 실제 설계에서는 반환값이나 별도의 자료 구조를 사용하는 방법도 고려한다.

count = 0 def factorial(n): global count count += 1 if n <= 1: return 1 return n * factorial(n - 1) print(factorial(4)) print(count)

코드 3 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ④
factorial은 n=4,3,2,1에서 총 4번 호출되며 count는 전역 변수이다.
개념 4. 단일 호출과 다중 호출

한 번의 함수 실행에서 자기 자신을 한 번 호출하면 단일 호출, 두 번 이상 호출하면 다중 호출 재귀이다. 다중 호출은 문제를 여러 갈래의 작은 문제로 나누지만 호출 수가 빠르게 증가할 수 있다.

아래 함수는 각 단계에서 두 개의 재귀 호출을 수행한다.

def branch(n): if n == 0: print("끝") return branch(n - 1) branch(n - 1) branch(2)

코드 4 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ③, ⑤
branch(2)는 branch(1)을 두 번, 각 branch(1)은 branch(0)을 두 번 호출하므로 “끝”은 4번 출력된다.
개념 5. 피보나치수와 중복 계산

피보나치수는 F₀=0, F₁=1, Fₙ=Fₙ₋₂+Fₙ₋₁로 정의된다. 이 관계를 그대로 코드로 옮기면 하나의 호출이 두 개의 호출로 나뉜다.

그러나 fib(3), fib(2)와 같은 같은 계산이 여러 번 반복되므로 n이 커질수록 호출 횟수가 급격히 증가한다.

def fib(n): if n <= 1: return n return fib(n - 2) + fib(n - 1) print(fib(6))

코드 5 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ②, ④, ⑤
0,1,1,2,3,5,8이므로 fib(6)은 8이다. 다중 호출 때문에 중복 계산이 발생한다.
개념 6. 하노이 탑의 재귀 설계

n개의 원판을 시작 기둥에서 도착 기둥으로 옮기려면 다음 세 단계가 필요하다.

  1. 위의 n-1개 원판을 보조 기둥으로 옮긴다.
  2. 가장 큰 원판을 도착 기둥으로 옮긴다.
  3. 보조 기둥의 n-1개 원판을 도착 기둥으로 옮긴다.

원판이 1개일 때 직접 이동하는 것이 종료 조건이다.

def hanoi(n, start, via, end): if n == 1: print(start, "->", end) return hanoi(n - 1, start, end, via) print(start, "->", end) hanoi(n - 1, via, start, end) hanoi(3, "A", "B", "C")

코드 6 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ③, ④
하노이 탑은 작은 원판 위에 큰 원판을 놓을 수 없으며, 3개 원판의 최소 이동 횟수는 2³-1=7회이다.
목표지향 통합 과제
피보나치수 함수에 전역 변수 또는 추가 반환값을 적용하여 전체 호출 횟수를 측정하고, n이 5, 10, 20일 때 호출 횟수가 어떻게 증가하는지 비교해 보자. 이어서 하노이 탑에서 원판 수 n에 따른 최소 이동 횟수를 표로 정리한다.

5. 학습 마무리 멘트

작은 문제를 믿는다는 것

긴 소설은 한 문장으로 완성되지 않습니다. 한 장면이 다음 장면을 부르고, 작은 갈등들이 모여 인물의 삶을 만들어 냅니다. 음악에서도 하나의 주제가 변주되고 다시 나타나며 전체 작품의 질서를 만듭니다.

재귀 함수는 큰 문제를 한 번에 해결하려 하지 않습니다. 지금 해결할 수 없는 문제를 더 작은 문제에게 맡기고, 그 작은 문제가 답을 가져오리라 믿습니다. 그러나 그 믿음은 막연하지 않습니다. 종료 조건이라는 확실한 바닥과, 문제 크기가 줄어든다는 논리 위에 서 있습니다.

피보나치수의 가지처럼 계산은 퍼지고, 하노이 탑의 원판처럼 문제는 이동합니다. 중요한 것은 복잡함을 두려워하지 않고 관계를 발견하는 일입니다. 좋은 문제 해결자는 모든 답을 한 번에 아는 사람이 아니라, 답이 생겨나는 구조를 설계하는 사람입니다.
