2. 학습 시작 멘트

입자 검출기에서 우주 통신까지: 순서가 중요한 과학

물리 실험의 입자 검출기는 짧은 시간 동안 들어온 수많은 신호를 순서대로 기록합니다. 먼저 들어온 신호를 뒤로 미루면 실제 사건의 시간 순서가 바뀌어 분석 결과가 왜곡될 수 있습니다. 화학 자동 분석 장비에서도 시료가 들어온 순서대로 처리되어야 실험 기록과 결과가 정확히 대응됩니다.

생명과학의 DNA 분석 장비는 연속적으로 들어오는 데이터를 버퍼에 저장한 뒤 앞에서부터 처리하고, 천문 관측소는 망원경에서 전달되는 관측 요청을 순서대로 관리합니다. 공학에서는 프린터 작업, 네트워크 패킷, 고객 호출, 센서 이벤트처럼 기다리는 자료를 공정하게 처리해야 할 때가 많습니다.

큐는 이러한 순서를 보존하는 데이터 구조입니다. 줄을 선 사람처럼 먼저 들어온 자료가 먼저 나갑니다. 오늘 우리는 단순히 리스트에 값을 넣고 빼는 것이 아니라, 시간과 순서를 공정하게 관리하는 구조를 설계합니다.

4. 개념 및 상세 설명 · 관련 코드 · 코드별 확인 문제

개념 1. 큐와 선입선출

큐는 먼저 들어온 자료가 먼저 나가는 선입선출 방식의 선형 데이터 구조이다. 삽입은 뒤쪽 rear에서, 삭제는 앞쪽 front에서 이루어진다.

자료를 10, 20, 30 순서로 삽입하면 삭제 순서도 10, 20, 30이다. 줄서기, 대기 번호, 네트워크 작업 처리와 같은 상황에 적합하다.

FIFOfrontrear
queue = [] queue.append(10) queue.append(20) queue.append(30) print(queue) print(queue.pop(0)) print(queue)

출력: [10, 20, 30] → 10 → [20, 30]

코드 1 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ④
10이 가장 먼저 들어왔으므로 가장 먼저 삭제된다. append는 리스트의 뒤쪽에 값을 추가한다.
개념 2. front와 rear, 기본 연산

front는 다음에 삭제될 자료가 있는 출구 쪽이고, rear는 새 자료가 들어오는 입구 쪽이다.

큐의 주요 연산에는 삽입, 삭제, 맨 앞 자료 확인, 크기 확인, 빈 큐 확인이 있다. 맨 앞 자료를 확인할 때는 삭제하지 않고 queue[0]을 읽는다.

queue = [5, 8, 12] front = queue[0] size = len(queue) is_empty = len(queue) == 0 print(front) print(size) print(is_empty)

코드 2 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ③, ⑤
큐에는 3개 자료가 있고 queue[0]은 값을 확인할 뿐 삭제하지 않는다.
개념 3. 리스트를 이용한 큐 구현

파이썬 리스트에서는 append()로 rear에 삽입하고 pop(0)으로 front에서 삭제할 수 있다.

원리는 쉽게 표현되지만 리스트의 첫 원소를 삭제하면 뒤의 원소들이 앞으로 이동해야 하므로 자료가 많을 때 비효율적일 수 있다.

def enqueue(queue, value): queue.append(value) def dequeue(queue): if not queue: return None return queue.pop(0) q = [] enqueue(q, "A") enqueue(q, "B") print(dequeue(q)) print(q)

코드 3 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ②, ③, ④
A가 먼저 삽입되었으므로 먼저 삭제된다. pop(0)은 첫 원소를 삭제한다.
개념 4. deque를 이용한 효율적인 큐

collections.deque는 양쪽 끝에서 자료를 빠르게 삽입·삭제할 수 있도록 만든 자료 구조이다. 큐에서는 append()와 popleft()를 사용한다.

리스트의 pop(0)과 달리 앞 원소를 삭제할 때 나머지 원소 전체를 이동시키지 않아 큐 구현에 더 적합하다.

from collections import deque q = deque() q.append(100) q.append(200) q.append(300) print(q.popleft()) print(q[0]) print(len(q))

코드 4 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ⑤
100을 삭제한 뒤 큐는 200, 300이 남아 길이는 2이다.
개념 5. 빈 큐와 안전한 삭제

빈 큐에서 삭제 연산을 수행하면 오류가 발생할 수 있다. 따라서 삭제 전에 큐가 비어 있는지 검사해야 한다.

if q:는 큐에 자료가 있을 때 참이고, if not q:는 큐가 비었을 때 참이다. 안전한 프로그램은 정상 입력뿐 아니라 빈 구조와 같은 경계 상황도 처리한다.

from collections import deque def safe_dequeue(q): if not q: return "비어 있음" return q.popleft() q = deque() print(safe_dequeue(q)) q.append("자료") print(safe_dequeue(q))

코드 5 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ③, ④
not q는 큐가 비었을 때 참이다. 빈 큐에서는 삭제하지 않고 안내 문자열을 반환한다.
개념 6. 큐를 활용한 작업 순서 처리

큐는 먼저 요청된 작업을 먼저 처리하는 상황에 적합하다. 아래 프로그램은 프린터 작업을 입력된 순서대로 처리한다.

처리할 때마다 front의 작업을 꺼내고, 큐가 빌 때까지 반복한다. 이는 실생활의 대기 번호, 서버 요청, 센서 이벤트 처리와 같은 원리이다.

from collections import deque jobs = deque(["보고서", "그래프", "사진"]) while jobs: current = jobs.popleft() print(current, "인쇄") print("모든 작업 완료")

코드 6 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ②, ④, ⑤
큐의 선입선출 원리에 따라 처음 저장된 보고서부터 처리하며, 큐가 비면 반복을 끝낸다.
목표지향 통합 과제
과학 실험 장비의 측정 요청을 순서대로 처리하는 큐 프로그램을 작성한다. 측정 이름을 삽입하고, 가장 먼저 들어온 요청을 삭제·처리하며, 현재 대기 중인 첫 요청과 전체 대기 수를 출력한다. 빈 큐 삭제도 안전하게 처리한다.

5. 학습 마무리 멘트

기다림에도 질서가 있다

공연장 앞에 선 줄, 병원에서 받은 대기 번호, 도서관에서 기다리는 예약 도서에는 공통된 약속이 있습니다. 먼저 기다린 사람의 시간을 먼저 존중한다는 것입니다.

큐는 자료를 저장하는 기술이지만, 그 안에는 순서를 지키는 태도가 담겨 있습니다. 누군가의 요청을 잊지 않고, 뒤에 온 일이 앞의 일을 함부로 밀어내지 않도록 합니다. 예술 공연의 장면도, 문학의 사건도, 음악의 음표도 순서가 바뀌면 전혀 다른 의미가 됩니다.

프로그래밍에서 좋은 구조를 선택한다는 것은 데이터의 의미를 존중하는 일입니다. 오늘 배운 큐는 우리에게 말합니다. 빠르게 처리하는 것만큼, 올바른 순서로 처리하는 것도 중요하다.
