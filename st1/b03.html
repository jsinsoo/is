2. 학습 시작 멘트

매 순간 가장 좋은 선택을 하면 결국 가장 좋은 결과가 될까?

여행 가방에 물건을 넣을 때 가장 비싼 물건부터 넣으면 항상 가장 가치 있는 가방이 될까요? 시험 공부를 할 때 가장 쉬운 문제부터 해결하면 항상 가장 높은 점수를 얻을까요? 눈앞에서 가장 좋아 보이는 선택과 전체 결과에서 가장 좋은 선택은 같을 때도 있고 다를 때도 있습니다.

컴퓨터 알고리즘에도 이런 전략이 있습니다. 매 단계에서 현재 가장 좋아 보이는 선택을 하고, 그 선택을 되돌리지 않고 다음 단계로 나아가는 탐욕법입니다. 탐욕법은 매우 빠르고 단순할 수 있지만, 잘못 적용하면 최적해를 놓칠 수 있습니다.

오늘은 탐욕법을 단순한 코딩 기법으로 외우지 않습니다. 왜 이 선택을 하는가, 이 선택이 다음 문제를 어떻게 바꾸는가, 언제 전체 최적해를 보장하며 어떤 반례에서 실패하는가를 직접 확인합니다.

4. 개념 및 상세 설명 · 관련 코드 · 코드별 확인 문제

개념 1. 탐욕법: 지금 가장 좋아 보이는 선택

탐욕법(greedy method)은 문제를 해결하는 각 단계에서 현재 기준으로 가장 좋아 보이는 선택을 하고, 그 선택을 되돌리지 않으면서 해를 만들어 가는 방법이다.

이때 한 단계에서 가장 좋아 보이는 선택을 지역 최적 선택이라고 한다. 탐욕법이 올바른 알고리즘이 되려면 이러한 지역 최적 선택들이 최종적으로 전체 최적해로 이어져야 한다.

지역 최적전체 최적선택 기준되돌리지 않음
numbers = [9, 4, 7, 2] best = numbers[0] for x in numbers: if x > best: best = x print(best)

코드 1 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
현재까지 가장 큰 값을 유지하는 단순한 선택 전략의 예이다. 탐욕법에서는 이러한 선택 기준이 전체 문제에서도 최적해를 보장하는지가 핵심이다.
개념 2. 동전 교환: 탐욕법이 잘 작동하는 사례

동전 교환 문제에서 흔히 사용하는 탐욕 전략은 가장 큰 동전부터 가능한 만큼 선택하는 것이다. 예를 들어 500원, 100원, 50원, 10원 동전으로 금액을 만들 때에는 이 방식이 최소 동전 수를 구하는 데 잘 작동한다.

하지만 “가장 큰 동전부터 선택한다”는 규칙 자체가 언제나 옳은 것은 아니다. 동전 체계에 따라 결과가 달라질 수 있으므로 탐욕 선택의 타당성을 확인해야 한다.

def coin_greedy(amount, coins): result = [] for coin in sorted(coins, reverse=True): while amount >= coin: amount -= coin result.append(coin) return result print(coin_greedy(760, [500, 100, 50, 10]))

코드 2 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
760원은 500+100+100+50+10으로 만들 수 있으며, 큰 동전부터 가능한 만큼 선택한다.
개념 3. 반례: 탐욕 선택이 항상 최적은 아니다

탐욕법을 이해할 때 가장 중요한 활동 중 하나는 반례(counterexample)를 찾는 것이다. 반례란 어떤 규칙이 항상 옳다는 주장을 깨뜨리는 하나의 사례이다.

동전이 [1, 3, 4]이고 6원을 만든다고 하자. 가장 큰 동전부터 선택하면 4+1+1로 3개를 사용하지만, 실제 최소 동전 수는 3+3의 2개이다. 즉, 지역 최적 선택이 전체 최적해로 이어지지 않는다.

def greedy(amount): coins = [4, 3, 1] result = [] for coin in coins: while amount >= coin: amount -= coin result.append(coin) return result print(greedy(6))

코드 3 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
6원에서 탐욕법은 4+1+1을 선택하지만 최적해는 3+3이다. 따라서 이 동전 체계에서는 탐욕 선택이 항상 최적을 보장하지 않는다.
개념 4. 회의실 배정: 종료 시간이 빠른 회의부터 선택

하나의 회의실에서 겹치지 않는 회의를 가능한 많이 선택하려면, 종료 시간이 가장 빠른 회의를 먼저 선택하는 탐욕 전략을 사용할 수 있다.

한 회의를 선택한 뒤에는 그 회의의 종료 시간 이후에 시작하는 회의들만 후보가 된다. 따라서 큰 문제는 “현재 회의를 선택한 뒤 남은 시간에서 다시 가장 빨리 끝나는 회의를 고르는 문제”로 줄어든다.

meetings = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 9), (5, 9), (6, 10), (8, 11)] meetings.sort(key=lambda x: x[1]) selected = [] end_time = 0 for start, end in meetings: if start >= end_time: selected.append((start, end)) end_time = end print(selected)

코드 4 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
종료 시간이 빠른 순으로 살펴보고 현재 선택과 겹치지 않는 회의를 채택한다.
개념 5. 문제 분해: 선택 이후 남는 문제를 바라보기

탐욕법은 단순히 “가장 큰 것 고르기”가 아니다. 좋은 탐욕 알고리즘은 현재 선택 이후에 남는 문제가 어떤 형태인지 분석한다.

회의실 배정에서 하나의 회의를 선택하면 남는 문제는 그 회의 종료 이후에 시작하는 회의들 중 최대한 많은 회의를 선택하는 문제가 된다. 이처럼 큰 문제를 더 작은 문제로 나누고 그 관계를 파악하는 것은 [12정과03-03]의 핵심이다.

문제 분해를 잘하면 다음 차시의 분할정복과 이후 동적계획법에서도 부분 문제 사이의 관계를 더 쉽게 찾을 수 있다.

def remaining(meetings, end_time): result = [] for start, end in meetings: if start >= end_time: result.append((start, end)) return result data = [(1,4), (3,5), (5,7), (8,11)] print(remaining(data, 4))

코드 5 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
선택 이후에 가능한 후보만 남기면 원래 문제를 더 작은 동일 유형의 문제로 해석할 수 있다.
개념 6. 탐욕법 검증: 성공 사례와 반례를 비교하기

탐욕법에서는 코드가 실행된다는 사실만으로 알고리즘이 옳다고 결론 내릴 수 없다. 반드시 선택 기준이 전체 최적해를 보장하는지 검토해야 한다.

작은 입력에서는 완전 탐색으로 가능한 해를 모두 조사하여 최적해를 구하고, 탐욕법의 결과와 비교할 수 있다. 두 결과가 다르면 해당 탐욕 규칙의 반례를 찾은 것이다.

따라서 탐욕 알고리즘 학습에서는 탐욕 선택 → 결과 확인 → 완전 탐색과 비교 → 반례 분석의 흐름이 중요하다.

from itertools import combinations coins = [1, 3, 4] target = 6 best = None # 작은 예시에서 가능한 조합을 비교하는 사고 실험 for count3 in range(3): for count4 in range(2): remain = target - 3*count3 - 4*count4 if remain >= 0: count1 = remain total_count = count1 + count3 + count4 if best is None or total_count < best: best = total_count print("최소 동전 수:", best)

코드 6 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
탐욕법은 선택 규칙의 타당성이 핵심이므로 성공 사례뿐 아니라 실패 사례와 반례를 함께 분석해야 한다.
목표지향 통합 과제
동전 체계 [1, 3, 4]와 [1, 5, 10, 50]에 대해 여러 목표 금액을 정하여 ① 가장 큰 동전부터 선택하는 탐욕 프로그램의 결과를 구하고, ② 작은 입력에서는 가능한 조합을 직접 비교하여 최소 동전 수를 확인하며, ③ 탐욕법이 성공하는 경우와 실패하는 경우를 표로 정리하자. 마지막으로 “탐욕 선택이 전체 최적해를 보장하려면 무엇을 확인해야 하는가?”를 자신의 말로 설명해 보자.

5. 학습 마무리 멘트

빠른 선택보다 중요한 것은 그 선택이 옳은 이유를 설명하는 것이다

탐욕법은 복잡한 미래를 모두 계산하지 않고 현재 가장 좋아 보이는 선택을 한다는 점에서 매력적입니다. 어떤 문제에서는 이 단순한 전략이 놀랍도록 정확하고 효율적인 답을 만듭니다.

하지만 오늘 동전 [1,3,4]의 반례에서 보았듯, 눈앞의 가장 큰 선택이 전체에서 가장 좋은 결과를 보장하지는 않습니다. 그래서 좋은 알고리즘은 단지 “이렇게 하면 된다”가 아니라 왜 이 선택이 안전한지, 어떤 조건에서 실패하는지를 함께 설명해야 합니다.

또한 하나의 선택을 하고 나면 문제는 더 작은 문제로 바뀝니다. 이 부분 문제의 구조와 관계를 발견하는 능력은 다음 차시의 분할정복, 그 다음의 동적계획법으로 이어집니다. 오늘의 핵심은 하나입니다. 알고리즘의 선택에는 반드시 근거가 있어야 합니다.
