2. 학습 시작 멘트

미지의 행성을 찾는 탐사선: 어디까지 조사해야 할까?

우주 탐사선이 새로운 행성 표면에서 생명체의 흔적을 찾는다고 생각해 봅시다. 탐사선은 한 지점만 보고 “없다”고 결론 내릴 수 없습니다. 갈 수 있는 위치를 정하고, 각 위치에서 어떤 이동을 할 수 있는지 알아야 하며, 목표가 무엇인지도 분명해야 합니다.

미로를 빠져나가는 로봇도 같습니다. 로봇의 현재 위치가 상태이고, 위·아래·왼쪽·오른쪽으로 움직이는 것이 연산이며, 출구에 도착하는 것이 목표 상태입니다. 가능한 상태와 이동을 연결하면 우리가 조사해야 할 전체 세계, 즉 상태 공간이 만들어집니다.

오늘은 컴퓨터에게 “정답을 찾아봐”라고 막연하게 말하지 않습니다. 어떤 상태를 만들고, 어떤 순서로 조사하고, 언제 하나의 후보가 완성되며, 무엇을 정답으로 인정할 것인지를 정확히 설계합니다. 이것이 탐색 알고리즘의 출발점입니다.

4. 개념 및 상세 설명 · 관련 코드 · 코드별 확인 문제

개념 1. 상태 · 연산 · 목표 상태

상태(state)는 문제 해결 과정의 한 순간을 표현한 정보이다. 숫자 맞히기 문제에서는 현재 선택한 숫자가 상태가 될 수 있고, 미로에서는 현재 위치가 상태가 될 수 있다.

연산(operation)은 한 상태를 다른 상태로 바꾸는 행동이다. 초기 상태는 탐색을 시작하는 상태이고, 목표 상태는 문제에서 원하는 조건을 만족하는 상태이다.

이러한 상태들을 가능한 연산으로 연결하여 만든 전체 구조가 상태 공간(state space)이다.

상태연산목표 상태상태 공간
start = 0 goal = 3 state = start while state != goal: print("현재 상태:", state) state += 1 print("목표 상태:", state)

상태 전이: 0 → 1 → 2 → 3

코드 1 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ③, ⑤
상태는 0에서 시작하여 +1 연산으로 변하고, 상태가 3이 되면 목표에 도달하여 반복을 종료한다.
개념 2. 완전 탐색: 가능한 후보를 모두 확인하기

완전 탐색(exhaustive search)은 문제에서 가능한 후보를 빠짐없이 생성하고 각 후보가 정답 조건을 만족하는지 검사하는 방법이다.

후보의 수가 작을 때는 구현이 단순하고 정답을 놓치지 않는다는 장점이 있다. 그러나 후보 수가 매우 많아지면 실행 시간이 급격히 증가할 수 있다.

아래 코드는 1~5에서 두 수를 선택하여 합이 6인 모든 순서쌍을 찾는다.

for a in range(1, 6): for b in range(1, 6): if a + b == 6: print(a, b)

출력: (1,5), (2,4), (3,3), (4,2), (5,1)

코드 2 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ④
a와 b 각각 5가지이므로 후보는 5×5=25개이다. 모든 후보를 조사하며, 합이 6인지 검사한다.
개념 3. 재귀함수로 이진 상태 공간 만들기

각 단계에서 선택지가 두 개라면 상태 공간은 나무처럼 두 갈래로 확장될 수 있다. 길이 n의 이진 문자열을 만들 때 각 위치에는 0 또는 1을 선택할 수 있다.

아래 함수에서 s는 현재까지 만든 상태이고, len(s) == n은 하나의 후보가 완성되었다는 종료 조건이다. 그 전에는 0을 붙이는 상태와 1을 붙이는 상태를 모두 탐색한다.

def binary(s, n): if len(s) == n: print(s) return binary(s + "0", n) binary(s + "1", n) binary("", 3)

출력 후보: 000, 001, 010, 011, 100, 101, 110, 111

코드 3 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ②, ③, ⑤
세 위치마다 0/1 두 선택이 있으므로 완성 후보는 2³=8개이다. 문자열 덧셈은 새 문자열을 만들어 전달한다.
개념 4. 부분집합 완전 탐색: 선택과 비선택

집합의 각 원소에 대해 “포함한다/포함하지 않는다”를 결정하면 모든 부분집합을 만들 수 있다. 원소가 n개이면 각 원소마다 선택이 2가지이므로 부분집합의 수는 2ⁿ개이다.

아래 코드는 i번째 원소를 포함하는 경우와 포함하지 않는 경우를 모두 재귀적으로 탐색한다.

nums = [1, 2, 3] def subsets(i, chosen): if i == len(nums): print(chosen) return subsets(i + 1, chosen + [nums[i]]) subsets(i + 1, chosen) subsets(0, [])

코드 4 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ④, ⑤
첫 호출은 현재 원소를 포함하고, 두 번째 호출은 포함하지 않는다. 아무 원소도 선택하지 않은 빈 집합도 하나의 부분집합이다.
개념 5. 순열 완전 탐색: 사용하지 않은 원소 고르기

순열은 서로 다른 원소를 순서를 고려하여 나열한 것이다. n개의 서로 다른 원소를 모두 나열하는 경우의 수는 n!이다.

순열 탐색에서는 현재까지 사용하지 않은 원소 하나를 선택하여 경로에 추가하고, 모든 원소가 선택되면 하나의 후보가 완성된다.

nums = [1, 2, 3] def perm(path): if len(path) == len(nums): print(path) return for x in nums: if x not in path: perm(path + [x]) perm([])

후보 수: 3! = 6

코드 5 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ④
순열은 순서를 고려한다. 3개의 서로 다른 원소를 모두 배열하는 경우는 3!=6개이다.
개념 6. 탐색 규모와 완전 탐색의 한계

완전 탐색은 가능한 후보를 모두 검사하므로 후보 수가 탐색 비용에 직접 영향을 준다. 길이 n의 이진 문자열이나 n개 원소의 부분집합은 2ⁿ개의 후보를 갖고, n개 원소의 순열은 n!개의 후보를 갖는다.

입력 크기가 조금만 커져도 후보 수가 매우 빠르게 증가할 수 있다. 그래서 완전 탐색은 정답을 놓치지 않는 기준 알고리즘이 되지만, 큰 입력에서는 다음 차시의 백트래킹·가지치기처럼 불필요한 상태를 줄이는 전략이 필요해진다.

import math for n in range(1, 8): print( n, "2^n =", 2 ** n, "n! =", math.factorial(n) )

코드 6 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ②, ③, ⑤
2⁵=32, 5!=120이다. 완전 탐색은 모든 후보를 조사하므로 후보 수의 증가가 큰 부담이 될 수 있다.
목표지향 통합 과제
숫자 [1, 2, 3, 4] 중 일부를 선택하여 합이 5가 되는 모든 부분집합을 찾는 프로그램을 작성해 보자. ① 상태는 무엇인가? ② 각 단계의 연산은 무엇인가? ③ 종료 조건은 무엇인가? ④ 목표 조건은 무엇인가? ⑤ 완전 탐색에서 생성되는 전체 부분집합은 몇 개인가?

5. 학습 마무리 멘트

탐색은 “정답을 찾는 기술”이기 전에 “가능성을 표현하는 기술”이다

과학자는 관찰 가능한 모든 경우를 한꺼번에 외우지 않습니다. 어떤 변수가 있고, 어떤 조건이 변하며, 어떤 결과를 찾는지 구조화합니다. 수학자는 가능한 경우를 체계적으로 분류하고, 실험가는 변인을 통제하며 하나씩 확인합니다.

탐색 알고리즘도 같은 사고를 사용합니다. 현재 상태가 무엇인지, 어떤 선택으로 다음 상태가 만들어지는지, 언제 하나의 후보가 완성되는지, 무엇이 정답인지 분명하게 정의합니다. 그러면 복잡해 보이던 문제가 하나의 상태 공간으로 바뀝니다.

오늘의 완전 탐색은 가장 단순하지만 매우 중요한 기준입니다. 모든 후보를 확인하기 때문에 정답을 놓치지 않습니다. 그리고 바로 그 점 때문에 다음 질문이 생깁니다. “정답이 될 가능성이 없는 상태까지 꼭 모두 가야 할까?” 다음 차시의 백트래킹과 가지치기는 이 질문에서 시작합니다.
