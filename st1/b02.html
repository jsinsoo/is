2. 학습 시작 멘트

미로에서 막다른 길을 만난 탐사 로봇

탐사 로봇이 미로의 모든 길을 끝까지 확인한다면 언젠가는 출구를 찾을 수 있습니다. 하지만 이미 벽으로 막힌 길, 같은 장소로 되돌아가는 길, 목표와 연결될 수 없는 길까지 계속 조사한다면 많은 시간이 낭비됩니다.

사람은 막다른 길을 만나면 출발점까지 처음부터 돌아가지 않습니다. 가장 최근의 갈림길로 되돌아가 아직 시도하지 않은 다른 길을 선택합니다. 그리고 어떤 길이 분명히 실패할 것이라고 판단되면 그 길 아래는 더 살펴보지 않습니다.

프로그래밍에서는 이러한 사고를 백트래킹과 가지치기로 표현합니다. 오늘은 1차시의 완전 탐색을 기준으로, 정답 가능성이 없는 상태를 어떻게 판별하고 얼마나 많은 탐색을 줄일 수 있는지 코드로 확인합니다.

학습목표

  3. 문제 조건을 이용하여 유망하지 않은 상태를 판별하는 가지치기 조건을 설계할 수 있다.

4. 개념 및 상세 설명 · 관련 코드 · 코드별 확인 문제

개념 1. 백트래킹: 선택하고, 탐색하고, 되돌아오기

백트래킹(backtracking)은 상태 공간을 탐색하다가 현재 선택으로 더 이상 적절한 해를 만들 수 없다고 판단되면 이전 상태로 돌아가 다른 선택을 시도하는 방법이다.

핵심 흐름은 선택 → 재귀 호출 → 되돌리기이다. 완전 탐색이 모든 후보를 끝까지 만든 뒤 검사한다면, 백트래킹은 탐색 과정에서 조건을 확인하며 불필요한 경로를 줄일 수 있다.

선택재귀되돌리기상태 공간
path = [] def choose(n): if len(path) == n: print(path) return for x in range(1, n + 1): if x not in path: path.append(x) # 선택 choose(n) # 탐색 path.pop() # 되돌리기 choose(3)

코드 1 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
append로 선택하고 재귀적으로 다음 상태를 탐색한 뒤 pop으로 이전 상태를 복원한다.
개념 2. 되돌리기가 필요한 이유: 상태 복원

재귀 호출에서 돌아온 뒤에는 다음 선택을 시험해야 한다. 이때 이전 선택의 흔적이 남아 있으면 서로 다른 후보가 섞이므로 상태 복원이 필요하다.

리스트를 직접 변경하는 방식에서는 append()로 추가한 뒤 반드시 대응되는 pop()으로 되돌리는 패턴을 자주 사용한다.

nums = [1, 2, 3] chosen = [] def make(i): if i == len(nums): print(chosen) return chosen.append(nums[i]) make(i + 1) chosen.pop() make(i + 1) make(0)

코드 2 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
선택한 경우를 탐색한 뒤 pop으로 상태를 복원해야 비선택 경우를 올바르게 탐색할 수 있다.
개념 3. 가지치기: 유망하지 않은 상태를 조기에 배제하기

가지치기(pruning)는 현재 상태가 목표 해로 이어질 가능성이 없다고 판단될 때 그 아래 상태를 더 이상 탐색하지 않는 것이다.

어떤 상태를 배제해도 정답을 놓치지 않는다는 근거가 중요하다. 예를 들어 모든 수가 양수인 부분합 문제에서 현재 합이 목표값보다 이미 크다면 이후 양수를 더해도 목표값으로 돌아갈 수 없으므로 탐색을 중단할 수 있다.

nums = [2, 3, 5, 7] target = 10 def search(i, total): if total == target: print("찾음:", total) return if i == len(nums) or total > target: return # 가지치기 search(i + 1, total + nums[i]) search(i + 1, total) search(0, 0)

코드 3 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
양수만 더하는 상황에서는 목표 합을 초과한 경로가 다시 목표값이 될 수 없으므로 안전하게 배제할 수 있다.
개념 4. 부분합 문제: 완전 탐색에서 백트래킹으로

부분합 문제에서는 각 원소를 선택/비선택하는 두 갈래 상태 공간을 만든다. 완전 탐색은 모든 2ⁿ개 부분집합을 끝까지 만들 수 있지만, 백트래킹은 중간 상태에서 목표 가능성을 검사해 일부 경로를 일찍 종료할 수 있다.

따라서 같은 정답을 찾더라도 방문한 상태 수가 달라질 수 있다. 이것이 기존 탐색 기반 알고리즘과 가지치기 알고리즘을 비교하는 핵심이다.

nums = [1, 4, 6, 9] target = 10 count = 0 def subset(i, total): global count count += 1 if total == target: return True if i == len(nums) or total > target: return False return (subset(i + 1, total + nums[i]) or subset(i + 1, total)) print(subset(0, 0)) print("방문 상태:", count)

코드 4 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
방문 횟수를 세면 완전 탐색과 개선된 탐색의 실제 탐색량을 비교할 수 있다.
개념 5. N-Queen: 충돌 상태를 즉시 배제하기

N-Queen 문제는 같은 행, 열, 대각선에서 서로 공격하지 않도록 N개의 퀸을 배치하는 문제이다. 한 행에 퀸 하나씩 놓는다면 다음 퀸의 열을 선택할 때 이미 놓인 퀸과 같은 열 또는 같은 대각선인지 검사할 수 있다.

충돌이 발생한 순간 그 아래 배치는 모두 정답이 될 수 없으므로 즉시 가지치기한다.

N = 4 board = [] def safe(row, col): for r, c in enumerate(board): if c == col: return False if abs(row - r) == abs(col - c): return False return True def queen(row): if row == N: print(board) return for col in range(N): if safe(row, col): board.append(col) queen(row + 1) board.pop() queen(0)

코드 5 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
safe가 충돌 여부를 검사하고, 안전한 상태만 다음 행으로 확장한다. 재귀 후 pop으로 직전 배치를 되돌린다.
개념 6. 완전 탐색과 가지치기 비교·분석

가지치기의 목적은 단순히 코드를 짧게 만드는 것이 아니라 정답 가능성이 없는 상태를 방문하지 않아 탐색량을 줄이는 것이다.

비교할 때는 같은 입력과 같은 정답 조건을 사용하고, 함수 호출 횟수·방문 노드 수·실행 시간 등을 측정한다. 단, 잘못된 가지치기 조건은 실제 정답을 제거할 수 있으므로 효율성보다 먼저 정확성을 검증해야 한다.

def full(i, total): global full_count full_count += 1 if i == len(nums): return total == target return (full(i+1, total+nums[i]) or full(i+1, total)) def pruned(i, total): global prune_count prune_count += 1 if total == target: return True if i == len(nums) or total > target: return False return (pruned(i+1, total+nums[i]) or pruned(i+1, total))

코드 6 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
정확성을 유지하면서 방문 상태 수나 실행 시간을 줄였는지를 비교해야 가지치기의 효과를 설명할 수 있다.
목표지향 통합 과제
1차시에서 작성한 부분집합 완전 탐색 프로그램에 방문 상태 수를 세는 변수를 추가한 뒤, 양수 부분합 문제에 안전한 가지치기 조건을 설계하여 적용하자. 두 프로그램이 같은 정답을 찾는지 확인하고, 방문 상태 수가 얼마나 달라지는지 표로 비교한 뒤 “왜 이 가지치기가 정답을 제거하지 않는가?”를 한 문장으로 설명해 보자.

5. 학습 마무리 멘트

좋은 탐색은 모든 길을 걷는 것이 아니라, 걸을 필요가 없는 길을 설명할 수 있는 탐색이다

완전 탐색은 가능한 모든 길을 조사하기 때문에 확실한 출발점이 됩니다. 하지만 실제 문제의 상태 공간은 매우 커질 수 있습니다. 이때 중요한 능력은 단순히 더 빠르게 반복하는 것이 아니라 어떤 경로가 더 이상 정답이 될 수 없는지 논리적으로 판단하는 것입니다.

백트래킹은 선택을 시도하고 실패하면 이전 상태로 돌아갑니다. 가지치기는 실패가 분명해진 순간 그 아래의 수많은 상태를 만들지 않습니다. 이 두 생각은 복잡한 문제를 다룰 때 계산량을 줄이는 강력한 도구가 됩니다.

그러나 가지를 많이 자르는 것 자체가 목표는 아닙니다. 잘못 자르면 정답도 사라집니다. 따라서 좋은 알고리즘은 정확성을 지키면서 불필요한 탐색을 줄이고, 그 개선을 비교 자료로 설명할 수 있어야 합니다.
