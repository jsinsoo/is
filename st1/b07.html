2. 학습 시작 멘트

좋은 프로젝트는 좋은 코드보다 먼저 좋은 문제에서 시작한다

프로그램을 잘 만드는 것과 좋은 프로젝트를 만드는 것은 조금 다릅니다. 아무리 정교한 코드라도 실제로 해결할 문제가 분명하지 않다면 프로젝트의 가치는 낮아질 수 있습니다.

학교생활만 살펴보아도 급식 대기시간, 분실물 관리, 실험 데이터 정리, 교실 에너지 사용, 동아리 일정 조정처럼 정보과학으로 개선할 수 있는 문제들이 있습니다. 중요한 것은 “앱을 만들자”가 아니라 누가 어떤 상황에서 어떤 불편을 겪고 있으며, 어떤 데이터와 기능으로 개선할 수 있는가를 먼저 찾는 것입니다.

오늘은 Ⅳ단원의 첫 차시입니다. 코드를 작성하기 전에 문제를 발견하고 요구를 분석한 뒤, 실제로 실행 가능한 프로젝트 계획서까지 설계해 봅니다.

3. 학습목표와 학습내용

학습목표

  1. 실생활에서 정보과학으로 해결할 수 있는 문제를 발견할 수 있다.
  2. 프로젝트의 사용자·입력·출력·제한 조건을 정의할 수 있다.

  5. 문제에 적합한 자료 구조와 알고리즘 후보를 선정하고 근거를 설명할 수 있다.
  6. 역할·일정·산출물·테스트 기준이 포함된 프로젝트 계획서를 작성할 수 있다.

4. 개념 및 상세 설명 · 관련 코드 · 코드별 확인 문제

개념 1. 실생활 문제 발견: '불편함'을 정보과학 문제로 바꾸기

정보과학 프로젝트의 출발점은 실생활에서 해결할 가치가 있는 문제를 발견하는 것이다. 단순한 아이디어가 아니라 실제 사용자, 상황, 데이터, 제약 조건이 있는 문제를 구체적으로 관찰해야 한다.

예를 들어 “급식 줄이 길다”라는 관찰을 “시간대별 대기 인원 데이터를 이용해 평균 대기시간을 줄일 수 있는 안내 시스템을 만들 수 있을까?”처럼 바꾸면 정보과학적으로 다룰 수 있는 문제에 가까워진다.

problems = [ "교실 전력 낭비", "급식 대기 시간", "분실물 찾기", "실험 데이터 정리" ] for p in problems: print("관찰 대상:", p)

코드 1 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
좋은 프로젝트 문제는 실제 상황에서 출발하고 정보과학의 개념·데이터·알고리즘으로 해결 가능하도록 구체화한다.
개념 2. 사용자·입력·출력·제한 조건 정의

문제를 발견했다면 다음 단계는 누구를 위한 문제인지, 어떤 입력을 받아 어떤 결과를 제공할지, 어떤 제한 조건이 있는지를 명확히 하는 것이다.

사용자, 입력, 출력, 제한 조건을 정의하면 프로젝트의 범위가 선명해지고 구현 과정에서 불필요한 기능을 줄일 수 있다. 이것은 요구 분석의 가장 기본적인 구조이다.

project = { "user": "학생", "input": "시간대별 대기 인원", "output": "예상 대기 시간", "constraint": "개인정보를 수집하지 않음" } for key, value in project.items(): print(key, ":", value)

코드 2 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
사용자·입력·출력·제한 조건은 문제를 구현 가능한 수준으로 구체화하는 핵심 항목이다.
개념 3. 해결 목표를 측정 가능하게 만들기

“더 편리하게 만든다”처럼 모호한 목표보다 무엇을 얼마나 개선할 것인지를 구체적으로 정의하면 프로젝트의 성공 여부를 평가하기 쉽다.

예를 들어 “분실물 찾기를 쉽게 한다” 대신 “분실물 등록 정보를 검색하여 10초 이내에 후보 목록을 보여 준다”처럼 기능과 성능 기준을 함께 정의할 수 있다.

goal = { "function": "분실물 검색", "criterion": "검색 결과 10초 이내 표시", "accuracy": "등록 정보와 일치하는 후보 제공" } for k, v in goal.items(): print(k, ":", v)

코드 3 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
측정 가능한 목표는 설계·구현·테스트 단계 전체를 연결하는 기준이 된다.
개념 4. 기능 분해: 큰 프로젝트를 작은 기능으로 나누기

프로젝트 전체를 한 번에 구현하기보다 입력, 처리, 저장, 분석, 출력 등 작은 기능으로 나누면 개발과 협업이 쉬워진다.

기능 분해를 통해 각 기능의 입력과 출력이 분명해지고, 팀원별 역할 분담과 모듈 통합도 체계적으로 할 수 있다. 함수와 모듈 설계는 기능 분해를 코드로 표현하는 대표적인 방법이다.

def load_data(): pass def analyze_data(data): pass def make_result(data): pass def show_result(result): pass # 입력 → 분석 → 결과 생성 → 출력

코드 4 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
기능 분해는 복잡한 프로젝트를 관리 가능한 작은 단위로 나누고 역할과 인터페이스를 분명하게 한다.
개념 5. 자료 구조와 알고리즘 후보 선정

문제에 필요한 기능을 정의한 뒤에는 어떤 자료 구조와 알고리즘이 적절한지 후보를 선정한다. 이때 이전 단원에서 학습한 스택·큐·그래프·탐색·탐욕·분할정복·동적계획법 등을 문제 특성과 연결할 수 있다.

예를 들어 대기열 처리는 큐, 연결 관계 탐색은 그래프와 BFS/DFS, 정렬된 데이터 검색은 이진 탐색이 후보가 될 수 있다. 중요한 것은 단순히 배운 알고리즘을 사용하는 것이 아니라 왜 그 방법이 문제 구조에 적합한지 근거를 제시하는 것이다.

needs = { "대기 순서 관리": "queue", "연결 관계 탐색": "graph + BFS", "정렬 데이터 검색": "binary search" } for problem, method in needs.items(): print(problem, "→", method)

코드 5 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
프로젝트 설계에서는 문제 구조에 맞는 자료 구조·알고리즘 후보를 선정하고 선택 근거를 설명해야 한다.
개념 6. 프로젝트 계획서: 역할·일정·산출물·테스트 기준

프로젝트 계획서는 단순한 주제 설명서가 아니라 문제 정의, 해결 목표, 입력·출력, 핵심 기능, 자료 구조·알고리즘, 테스트 기준, 역할, 일정, 산출물을 연결하는 실행 문서이다.

좋은 계획서는 프로젝트가 진행될수록 수정될 수 있지만, 최소한 누가 무엇을 언제까지 만들고 어떤 기준으로 결과를 확인할지 알 수 있어야 한다.

plan = { "problem": "급식 대기시간 예측", "output": "예상 대기시간", "algorithm": "평균·조건 분류", "test": "예측값과 실제값 비교", "owner": "데이터팀", "deadline": "9월 30일" } for item in plan: print(item, ":", plan[item])

코드 6 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
프로젝트 계획서는 문제 정의에서 구현·검증·협업까지 이어지는 전체 수행 과정을 구체화한다.
목표지향 통합 과제 · 프로젝트 계획서 작성
과학·수학·환경·학교생활 중 한 영역에서 문제를 하나 선정하여 다음 8개 항목을 작성하자. ① 문제 상황 ② 해결 목표 ③ 입력 데이터 ④ 출력 결과 ⑤ 핵심 기능 ⑥ 사용할 자료 구조·알고리즘 ⑦ 테스트 기준 ⑧ 역할과 일정. 작성 후 짝과 계획서를 교환하여 “문제 정의가 구체적인가?”, “입력과 출력이 연결되는가?”, “알고리즘 선택 근거가 있는가?”, “테스트 가능한가?”의 네 기준으로 상호 점검한다.
