2. 학습 시작 멘트

어제 계산한 답을 오늘 또 처음부터 계산해야 할까?

복잡한 문제를 작은 문제로 나누는 것은 좋은 전략입니다. 그런데 작은 문제를 자세히 살펴보니 똑같은 문제가 여러 번 등장한다면 어떨까요? 매번 처음부터 다시 계산하는 것은 정확하지만 불필요한 작업이 많아집니다.

피보나치 수열의 단순 재귀 코드는 매우 자연스럽지만, 호출 트리를 그려 보면 같은 fib(3), fib(2)가 반복해서 등장합니다. 컴퓨터에게도 우리가 이미 계산한 답을 기억하게 할 수 있습니다.

오늘은 중복되는 부분 문제를 발견하고 → 결과를 저장하고 → 필요할 때 재사용하는 동적 계획법을 학습합니다. 같은 정답을 구하는 단순 재귀, 메모이제이션, 테이블 방식의 계산 과정을 직접 비교합니다.

4. 개념 및 상세 설명 · 관련 코드 · 코드별 확인 문제

개념 1. 중복 부분 문제: 같은 계산이 왜 반복될까?

동적 계획법(Dynamic Programming, DP)의 출발점은 큰 문제를 작은 부분 문제로 나누었을 때 같은 부분 문제가 여러 번 다시 등장하는지 찾는 것이다.

단순 재귀 피보나치에서는 fib(5)를 계산하는 과정에서 fib(3), fib(2) 같은 값이 여러 경로에서 반복 계산된다. 이미 계산한 값을 다시 계산하지 않는다면 호출 횟수를 크게 줄일 수 있다.

count = 0 def fib(n): global count count += 1 if n <= 1: return n return fib(n - 1) + fib(n - 2) print(fib(6)) print("호출 횟수:", count)

코드 1 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
단순 재귀 피보나치는 같은 작은 문제를 반복 계산한다. 이 중복을 발견하는 것이 DP 설계의 첫 단계이다.
개념 2. 메모이제이션: 계산한 결과를 저장하고 재사용하기

메모이제이션(memoization)은 재귀 호출의 결과를 저장해 두었다가 같은 입력이 다시 등장하면 저장된 값을 즉시 사용하는 방식이다.

아래 코드에서는 딕셔너리 memo가 이미 계산한 피보나치 값을 저장한다. n not in memo인 경우에만 실제 계산을 수행하므로 중복 계산을 줄인다.

memo = {0: 0, 1: 1} def fib(n): if n not in memo: memo[n] = fib(n - 1) + fib(n - 2) return memo[n] print(fib(10)) print(memo)

코드 2 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
메모이제이션의 핵심은 재귀 구조를 유지하면서 이미 계산한 결과를 저장하고 재사용하는 것이다.
개념 3. 테이블 방식: 작은 문제부터 차례로 계산하기

동적 계획법은 재귀로만 구현하는 것이 아니다. 테이블 방식(tabulation)은 가장 작은 부분 문제부터 시작해 필요한 값을 순서대로 계산하여 리스트나 배열에 저장한다.

피보나치 수열에서는 dp[i-1]과 dp[i-2]가 이미 계산되어 있으므로 두 값을 이용해 dp[i]를 한 번만 계산한다.

def fib_dp(n): if n <= 1: return n dp = [0] * (n + 1) dp[1] = 1 for i in range(2, n + 1): dp[i] = dp[i - 1] + dp[i - 2] return dp[n] print(fib_dp(10))

정답: ①, ②, ③
테이블 방식은 작은 부분 문제의 답을 순서대로 저장하고 그 값을 이용해 다음 문제를 해결한다.
개념 4. 점화 관계와 상태: 무엇을 저장할 것인가?

동적 계획법에서는 단순히 리스트를 사용하는 것이 아니라 무엇을 하나의 부분 문제로 정의할지가 중요하다. 이때 부분 문제를 나타내는 정보를 상태(state)라고 볼 수 있다.

계단을 1칸 또는 2칸씩 오를 수 있을 때 dp[i]를 “i번째 계단까지 올라가는 방법의 수”라고 정의하면, 마지막 이동은 1칸 전 또는 2칸 전에서 오므로 이전 두 상태의 답으로 현재 답을 계산할 수 있다.

def stairs(n): if n <= 1: return 1 dp = [0] * (n + 1) dp[0] = 1 dp[1] = 1 for i in range(2, n + 1): dp[i] = dp[i - 1] + dp[i - 2] return dp[n] print(stairs(5))

정답: ①, ②, ③
DP 설계에서는 상태의 의미와 상태 사이의 관계를 명확히 정의하는 것이 중요하다.
개념 5. 단순 재귀와 메모이제이션의 호출 횟수 비교

같은 정답을 구하는 두 알고리즘이라도 계산 과정은 크게 다를 수 있다. 단순 재귀는 중복 부분 문제를 반복 계산하지만 메모이제이션은 처음 계산한 결과를 저장한다.

따라서 정답의 동일성뿐 아니라 함수 호출 횟수, 중복 계산 횟수, 실행 시간 등을 비교하면 동적 계획법의 개선 효과를 더 구체적으로 설명할 수 있다.

plain_count = 0 memo_count = 0 memo = {0: 0, 1: 1} def plain(n): global plain_count plain_count += 1 if n <= 1: return n return plain(n-1) + plain(n-2) def fast(n): global memo_count memo_count += 1 if n not in memo: memo[n] = fast(n-1) + fast(n-2) return memo[n] print(plain(10), plain_count) print(fast(10), memo_count)

코드 5 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
같은 결과를 얻더라도 메모이제이션은 중복 부분 문제를 저장하여 단순 재귀보다 불필요한 계산을 줄일 수 있다.
개념 6. 메모이제이션과 테이블 방식 비교

메모이제이션과 테이블 방식은 모두 부분 문제의 결과를 저장하여 다시 활용한다는 공통점이 있다. 차이는 계산 순서에 있다.

메모이제이션은 필요한 큰 문제에서 재귀적으로 내려가며 필요한 상태를 계산하는 하향식(top-down) 접근이고, 테이블 방식은 작은 상태부터 순서대로 계산하는 상향식(bottom-up) 접근이다.

문제의 상태 구조, 필요한 상태의 범위, 재귀 깊이 등을 고려하여 적절한 구현 방식을 선택할 수 있다.

# 상향식 피보나치 def bottom_up(n): if n <= 1: return n a, b = 0, 1 for _ in range(2, n + 1): a, b = b, a + b return b print(bottom_up(10))

코드 6 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
동적 계획법은 메모이제이션과 반복 기반 테이블 방식으로 구현할 수 있으며 핵심은 부분 해의 저장과 재사용이다.
목표지향 통합 과제
fib(5), fib(10), fib(20)을 단순 재귀와 메모이제이션으로 각각 실행하고 함수 호출 횟수를 기록하자. 그다음 같은 피보나치 수열을 테이블 방식으로 구현하여 ① 상태의 의미 ② 점화 관계 ③ 저장되는 값 ④ 중복 계산 여부를 비교표로 정리한다. 마지막으로 계단 오르기 문제에서 dp[i]의 의미를 직접 정의하고 점화 관계를 코드로 구현해 보자.

5. 학습 마무리 멘트

좋은 알고리즘은 이미 해결한 문제를 다시 처음부터 풀지 않는다

분할정복에서는 큰 문제를 작은 문제로 나누었습니다. 오늘은 그 부분 문제들이 서로 겹칠 때 어떤 일이 일어나는지 살펴보았습니다. 같은 작은 문제가 계속 나타난다면 매번 다시 계산하는 대신 답을 저장하여 재사용할 수 있습니다.

메모이제이션은 필요한 문제에서 아래로 내려가며 계산 결과를 기억하고, 테이블 방식은 작은 문제부터 차례대로 답을 쌓아 갑니다. 구현 방식은 다르지만 둘 다 부분 문제의 관계를 이용하고 이미 계산한 결과를 재사용한다는 공통점을 가집니다.

동적 계획법의 핵심은 리스트나 딕셔너리를 사용하는 것이 아닙니다. 무엇을 상태로 정의할 것인지, 어떤 부분 문제가 반복되는지, 이전 상태의 답으로 현재 상태의 답을 어떻게 만들 것인지를 설계하는 것입니다.
