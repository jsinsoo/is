2. 학습 시작 멘트

10차시의 목표는 더 배우는 것이 아니라, 배운 것을 하나의 구조로 연결하는 것입니다

1~6차시에서는 상태 공간을 탐색하고, 불필요한 상태를 줄이고, 현재의 최선을 선택하고, 문제를 나누고, 이전 계산을 저장하며, 마지막에는 그 알고리즘이 얼마나 효율적인지 비교했습니다. 7~9차시에서는 실생활 문제를 발견하고, 프로젝트를 설계하고, 협업하여 구현하고, 테스트와 디버깅을 거쳐 기능적·윤리적으로 평가하고 개선했습니다.

오늘은 이 내용들을 따로 외우지 않습니다. 문제의 구조 → 알고리즘 선택 → 코드 구현 → 효율성 분석 → 프로젝트 적용 → 테스트 → 평가 → 개선이라는 하나의 문제 해결 흐름으로 연결합니다.

2차고사에서는 용어를 기억하는 것만큼 코드를 읽고 실행 과정을 추적하는 능력, 알고리즘을 선택한 이유를 설명하는 능력, 반례와 복잡도를 통해 한계를 분석하는 능력이 중요합니다. 자신의 프로젝트도 같은 관점으로 돌아보며 “왜 그렇게 설계했는가?”를 설명할 수 있도록 최종 개념망을 완성해 봅시다.

4. 개념 및 상세 설명 · 관련 코드 · 코드별 확인 문제

개념 1. 알고리즘 개념망: 완전 탐색에서 가지치기·탐욕·분할정복·DP로

2차고사 알고리즘 영역의 핵심은 알고리즘 이름을 따로 암기하는 것이 아니라 문제의 구조에 따라 어떤 전략을 선택해야 하는지 연결해서 이해하는 것이다.

완전 탐색은 가능한 경우를 빠짐없이 확인하는 기준점이 된다. 가지치기·백트래킹은 해가 될 수 없는 상태를 일찍 제외한다. 탐욕법은 매 단계에서 현재 가장 좋아 보이는 선택을 하고, 분할정복은 문제를 독립적인 작은 문제로 나누어 해결한 뒤 결합한다. 동적계획법(DP)은 겹치는 부분 문제의 결과를 저장하여 중복 계산을 줄인다.

따라서 시험에서는 “어떤 알고리즘인가?”뿐 아니라 왜 이 전략이 적합한가, 어떤 조건에서 실패할 수 있는가, 다른 전략과 비교하면 무엇이 달라지는가를 설명할 수 있어야 한다.

완전 탐색가지치기탐욕법분할정복·DP
def search(values, target): for x in values: if x == target: return True return False values = [4, 7, 1, 9, 3] print(search(values, 9)) print(search(values, 8))

정답: ①, ②, ③
알고리즘은 문제 구조에 따라 선택한다. 완전 탐색을 기준으로 불필요한 상태 제거, 지역 최선 선택, 문제 분할, 중복 부분 문제 저장의 차이를 비교해야 한다.
개념 2. 상태 공간·백트래킹·가지치기: 탐색해야 할 경우를 구조화하기

상태 공간은 문제 해결 과정에서 나타날 수 있는 상태와 상태 사이의 이동을 구조적으로 표현한 것이다. 모든 상태를 탐색하면 정답을 찾을 수 있지만 상태 수가 빠르게 증가할 수 있다.

백트래킹은 선택을 진행하다가 현재 상태가 해가 될 가능성이 없다고 판단되면 이전 상태로 돌아가 다른 선택을 시도한다. 이때 더 이상 확인할 필요가 없는 상태 공간을 제외하는 판단이 가지치기(pruning)이다.

가지치기의 핵심은 단순히 탐색 횟수를 줄이는 것이 아니라 정답 가능성이 있는 상태를 잘못 제거하지 않는 조건을 설계하는 것이다. 따라서 완전 탐색과 비교하여 탐색 범위와 결과의 정확성을 함께 설명해야 한다.

상태 공간백트래킹가지치기 조건탐색 범위
def choose(nums, start, picked, limit): if sum(picked) > limit: return print(picked) for i in range(start, len(nums)): choose(nums, i + 1, picked + [nums[i]], limit) choose([2, 4, 6], 0, [], 6)

코드 2 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
백트래킹은 상태 공간을 탐색하되 가능성이 없는 분기를 조기에 중단한다. 가지치기 조건의 타당성이 정확성과 효율성을 함께 결정한다.
개념 3. 탐욕법과 반례: 현재의 최선이 전체의 최선인지 검증하기

탐욕법(greedy)은 각 단계에서 현재 기준으로 가장 좋은 선택을 반복하여 해를 구성한다. 구현이 단순하고 빠른 경우가 많지만 모든 문제에서 최적해를 보장하지는 않는다.

따라서 탐욕법을 사용할 때는 선택 기준이 무엇인지 분명히 하고, 그 선택이 이후 선택을 방해하지 않으며 전체 최적해로 이어지는지 검토해야 한다. 작은 입력을 직접 계산하여 반례를 찾는 것은 탐욕 전략의 한계를 확인하는 중요한 방법이다.

시험에서는 탐욕 코드의 실행 결과뿐 아니라 “왜 이 문제에서는 맞는가?”, “어떤 입력에서는 틀릴 수 있는가?”를 설명하는 문제가 중요하다.

지역 최적전체 최적선택 기준반례
coins = [4, 3, 1] amount = 6 count = 0 for coin in coins: while amount >= coin: amount -= coin count += 1 print("선택:", coin) print("동전 수:", count)

코드 3 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
탐욕법은 빠르고 단순하지만 최적성 보장이 필요하다. 4·3·1 동전에서 6은 큰 동전 우선 전략의 반례가 되어 탐욕 선택을 검증해야 함을 보여 준다.
개념 4. 분할정복과 동적계획법: 문제를 나누는 두 가지 관점 비교

분할정복은 큰 문제를 더 작은 문제로 나누고 각각 해결한 뒤 결과를 결합한다. 부분 문제가 비교적 독립적일 때 효과적이며 이진 탐색, 병합 정렬 등에서 대표적으로 나타난다.

동적계획법도 큰 문제를 작은 부분 문제로 나누지만, 같은 부분 문제가 반복해서 등장하는 중복 부분 문제와 작은 문제의 최적해가 큰 문제 해결에 활용되는 구조에 주목한다. 이미 계산한 결과를 저장하여 다시 계산하지 않는 것이 핵심이다.

두 전략 모두 문제 분해를 사용하지만 부분 문제의 독립성·중복 여부·결과 저장 방식에서 차이가 있다. 코드를 보고 재귀 호출 구조와 저장 테이블을 확인하면 전략을 구별할 수 있다.

분할결합중복 부분 문제메모이제이션·테이블
def fib_dp(n): if n <= 1: return n dp = [0] * (n + 1) dp[1] = 1 for i in range(2, n + 1): dp[i] = dp[i-1] + dp[i-2] return dp[n] print(fib_dp(8))

코드 4 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
분할정복과 DP 모두 문제를 나누지만 DP는 중복 부분 문제의 결과를 저장하여 재사용한다. 코드에서 상태와 점화식, 저장 구조를 찾는 연습이 중요하다.
개념 5. 알고리즘 복잡도와 선택 근거: 입력 크기 n과 연산량 연결하기

시간 복잡도는 입력 크기 n이 증가할 때 필요한 연산량이 어떤 비율로 증가하는지를 나타낸다. 대표적으로 O(1), O(log n), O(n), O(n log n), O(n²) 등을 비교한다.

실제 실행 시간은 컴퓨터 성능, 언어, 입력 데이터 등에 영향을 받지만 빅오는 특정 컴퓨터에 덜 의존하여 알고리즘의 증가 경향을 비교할 수 있게 한다.

알고리즘 선택에서는 정확성만이 아니라 입력 크기, 시간·메모리 제한, 구현 난이도와 문제 구조를 함께 고려해야 한다. 따라서 “A가 더 빠르다”보다 어떤 입력 규모와 조건에서 왜 더 적합한지 설명하는 것이 중요하다.

입력 크기 n연산 횟수빅오선택 근거
def count_pairs(n): count = 0 for i in range(n): for j in range(n): count += 1 return count for n in [10, 100, 1000]: print(n, count_pairs(n))

코드 5 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
중첩 반복은 대표적인 O(n²) 구조이다. 빅오는 입력 증가에 따른 연산량의 증가 경향을 표현하며 알고리즘 선택의 근거가 된다.
개념 6. 정보과학 프로젝트 전체 흐름과 성찰: 문제 발견에서 개선까지

Ⅳ단원의 프로젝트는 서로 분리된 활동이 아니라 하나의 연속적인 문제 해결 과정이다. 문제 발견 → 요구 분석·설계 → 오픈소스·라이브러리 활용 → 협업 구현 → 테스트·디버깅 → 기능적·윤리적 평가 → 개선의 흐름으로 연결된다.

최종 성찰에서는 단순히 “프로젝트를 잘했다”라고 쓰는 것이 아니라, 처음 정의한 문제와 목표가 실제 구현 결과에 반영되었는지, 알고리즘 선택은 적절했는지, 테스트에서 무엇이 발견되었는지, 개인정보·편향·저작권 등 윤리 요소를 어떻게 고려했는지 근거를 들어 설명해야 한다.
