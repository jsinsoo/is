2. 학습 시작 멘트

1초 차이가 아니라, 입력이 커질 때의 변화를 보자

학생 10명의 자료를 처리할 때는 어떤 프로그램을 사용해도 금방 끝날 수 있습니다. 하지만 학생이 1만 명, 데이터가 100만 개가 된다면 상황은 달라집니다. 작은 입력에서 비슷해 보이던 두 알고리즘이 큰 입력에서는 전혀 다른 속도를 보일 수 있습니다.

그래서 알고리즘의 성능을 판단할 때는 한 번의 실행 시간만 보지 않습니다. 입력 크기 n이 커질 때 핵심 연산 횟수가 어떤 속도로 증가하는가를 분석합니다. 이를 간단하게 표현하는 도구가 빅오 표기법입니다.

오늘은 Ⅲ단원의 마지막 차시입니다. 앞에서 배운 탐색, 백트래킹, 탐욕법, 분할정복, 동적계획법을 다시 꺼내어 정확성·적용 조건·시간 복잡도·실제 실행 시간이라는 기준으로 비교해 봅니다.

4. 개념 및 상세 설명 · 관련 코드 · 코드별 확인 문제

개념 1. 알고리즘 성능과 입력 크기 n

같은 문제를 해결하는 프로그램이라도 입력의 크기가 커질수록 필요한 계산량은 서로 다르게 증가한다. 알고리즘의 성능을 비교할 때는 단순히 한 번의 실행 시간이 아니라 입력 크기 n이 증가할 때 핵심 연산 횟수가 어떻게 증가하는가를 살펴본다.

예를 들어 리스트의 첫 원소를 한 번 확인하는 코드는 입력 크기와 관계없이 거의 일정한 연산을 하지만, 모든 원소를 한 번씩 확인하는 코드는 n에 비례하여 연산 횟수가 증가한다.

def first_value(data): return data[0] def total(data): s = 0 for x in data: s += x return s data = list(range(100)) print(first_value(data)) print(total(data))

정답: ①, ②, ③
입력 크기 n에 따라 핵심 연산이 어떻게 증가하는지 관찰하는 것이 시간 복잡도 분석의 출발점이다.
개념 2. 빅오 표기법: 증가하는 정도를 표현하기

빅오(Big-O) 표기법은 입력 크기가 커질 때 알고리즘의 연산량이 증가하는 정도를 간단히 표현한다. 대표적으로 O(1), O(log n), O(n), O(n log n), O(n²)을 비교할 수 있다.

빅오에서는 입력이 매우 커질 때의 증가 경향에 초점을 두므로 상수배나 낮은 차수 항은 보통 생략한다. 예를 들어 3n + 5처럼 증가하는 연산량은 O(n)으로 표현한다.

def constant_work(n): return n * 2 def linear_work(n): count = 0 for i in range(n): count += 1 return count print(constant_work(1000)) print(linear_work(1000))

코드 2 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
빅오는 실제 초 단위 시간을 직접 나타내는 값이 아니라 입력 증가에 따른 연산량의 성장 정도를 나타낸다.
개념 3. O(log n): 이진 탐색의 범위 감소

정렬된 자료에서 이진 탐색은 한 번 비교할 때마다 탐색 범위를 대략 절반으로 줄인다. n개의 후보가 n/2, n/4, n/8처럼 줄어들기 때문에 반복 횟수는 n에 비례하지 않고 O(log n) 수준으로 증가한다.

이는 모든 원소를 처음부터 차례로 확인하는 O(n) 선형 탐색과 중요한 차이를 만든다.

def binary_search(a, target): left, right = 0, len(a) - 1 while left <= right: mid = (left + right) // 2 if a[mid] == target: return mid elif target < a[mid]: right = mid - 1 else: left = mid + 1 return -1

정답: ①, ②, ③
이진 탐색은 정렬된 자료의 구조를 이용해 후보 범위를 반복적으로 절반씩 줄인다.
개념 4. O(n²): 중첩 반복문의 증가

반복문 하나가 n번 실행되고 그 안의 반복문도 대략 n번 실행된다면 핵심 연산은 약 n×n번 수행된다. 이런 형태의 대표적인 시간 복잡도는 O(n²)이다.

n이 10배가 될 때 연산량은 대략 100배 수준으로 증가할 수 있으므로 큰 입력에서는 O(n) 알고리즘과 성능 차이가 매우 커질 수 있다.

def count_pairs(data): count = 0 for i in range(len(data)): for j in range(len(data)): count += 1 return count print(count_pairs([1, 2, 3, 4]))

코드 4 확인 문제: 옳은 것을 모두 고르시오. (3개)

정답: ①, ②, ③
두 반복문이 각각 n번 실행되므로 핵심 연산 횟수는 n²에 비례한다.
개념 5. 실제 실행 시간 측정: time.perf_counter()

이론적 시간 복잡도와 함께 실제 프로그램의 실행 시간을 측정하면 알고리즘의 성능을 실험적으로 비교할 수 있다. 파이썬의 time.perf_counter()를 이용하면 실행 전후의 시각 차이를 측정할 수 있다.

다만 실제 시간은 컴퓨터 성능, 운영체제 상태, 입력 데이터, 다른 프로그램의 실행 등에 영향을 받는다. 따라서 한 번의 측정값만으로 일반적인 복잡도를 결정해서는 안 된다.

import time def linear_sum(n): s = 0 for i in range(n): s += i return s start = time.perf_counter() linear_sum(100000) end = time.perf_counter() print("실행 시간:", end - start)

정답: ①, ②, ③
실행 시간 측정은 성능 실험에 유용하지만 빅오와 동일한 개념은 아니며 환경과 입력의 영향을 고려해야 한다.
개념 6. 알고리즘 선택: 정확성·복잡도·적용 조건을 함께 보기

좋은 알고리즘을 선택할 때는 시간 복잡도 하나만 보는 것이 아니라 정확성, 입력 조건, 자료의 크기, 구현 비용, 메모리 사용, 실제 실행 시간 등을 함께 고려해야 한다.

이번 Ⅲ단원에서 학습한 완전 탐색, 백트래킹, 탐욕법, 분할정복, 동적계획법은 서로 다른 문제 구조에 적합하다. 따라서 문제의 상태 공간과 부분 문제 관계를 먼저 분석하고, 적용 조건과 성능을 근거로 알고리즘을 선택해야 한다.

def linear_search(a, target): for i in range(len(a)): if a[i] == target: return i return -1 # 정렬된 자료라면 이진 탐색도 후보가 될 수 있다. data = [2, 5, 8, 12, 16, 23, 38] print(linear_search(data, 23)) print(binary_search(data, 23))

알고리즘 선택은 정확한 결과를 전제로 문제 조건과 이론·실제 성능을 함께 비교하여 판단한다.
목표지향 통합 과제
입력 크기를 1,000 → 10,000 → 100,000으로 바꾸어 O(1), O(n), 가능한 범위의 O(n²) 예제 실행 시간을 측정하고 표로 기록하자. 이어서 같은 값을 찾는 선형 탐색과 이진 탐색을 비교하여 이론적 시간 복잡도와 실제 측정값을 함께 해석한다. 마지막으로 완전 탐색·백트래킹·탐욕법·분할정복·동적계획법 중 하나를 선택해야 하는 새로운 문제 상황을 만들고, 정확성·적용 조건·시간 복잡도를 근거로 선택 이유를 서술하자.

5. 학습 마무리 멘트

좋은 알고리즘은 정답뿐 아니라 선택의 근거를 설명할 수 있다

Ⅲ단원에서 우리는 같은 문제를 바라보는 여러 방법을 배웠습니다. 모든 상태를 확인할 수도 있고, 가능성이 없는 상태를 버릴 수도 있으며, 현재의 좋은 선택을 이어 갈 수도 있습니다. 문제를 절반으로 나누거나 이미 계산한 답을 저장해 다시 사용할 수도 있습니다.

오늘 배운 시간 복잡도는 이러한 방법들을 비교하는 하나의 공통 언어입니다. O(1), O(log n), O(n), O(n log n), O(n²)은 단순한 기호가 아니라 입력이 커질 때 계산량이 어떻게 성장하는지를 설명합니다.

그러나 가장 작은 빅오만 찾는 것이 알고리즘 설계의 전부는 아닙니다. 먼저 정확해야 하고, 문제의 조건에 적용 가능해야 하며, 시간과 공간, 구현의 복잡성도 함께 고려해야 합니다. 좋은 알고리즘 선택은 결국 왜 이 방법이 이 문제에 적합한지 근거를 제시하는 일입니다.
