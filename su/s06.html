Ⅰ. 가지치기·탐욕 전략·완전 탐색 학습자료

성취 목표
문제의 상태 공간에서 탐색하지 않아도 되는 상태를 판단하는 기준을 설계하고, 가지치기를 적용한 탐색과 완전 탐색을 비교하여 정확성과 효율성을 분석한다.

1. 문제 상황

수 목록 [3, 7, 11, 14, 18, 21]에서 일부 수를 선택하여 합이 32가 되는 모든 부분집합을 찾는다.

완전 탐색

각 수를 선택하거나 선택하지 않는 모든 경우를 탐색한다.

수의 개수가 n개이면 최대 2ⁿ개의 부분집합을 확인한다.

가지치기

목표에 도달할 가능성이 없는 상태를 미리 판단하여 탐색에서 제외한다.

정답은 유지하면서 방문 상태 수를 줄이는 것이 목표이다.

2. 상태 공간 구조

현재 수 확인→ 선택또는 미선택→ 다음 수로 이동
구성 요소정의
상태(index, current_sum, selected)
초기 상태(0, 0, [])
목표 상태current_sum == 32
전이 1현재 수를 선택하고 다음 인덱스로 이동
전이 2현재 수를 선택하지 않고 다음 인덱스로 이동
종료 조건목표 합 도달 또는 모든 수 확인 완료

3. 가지치기 기준

가지치기 1

current_sum > target

모든 수가 양수이므로 현재 합이 이미 목표보다 크면 이후 수를 추가해도 합이 더 커질 뿐이다.

가지치기 2

current_sum + suffix_sum[index] < target

남은 수를 모두 더해도 목표에 도달하지 못하면 해당 상태 아래는 더 탐색할 필요가 없다.

4. 탐욕 전략과의 비교

방법 핵심 원리 정답 보장 이 문제에서의 특징
완전 탐색 모든 선택·미선택 경우 확인 보장됨 정확하지만 상태 수가 많음
가지치기 탐색 불가능한 상태를 안전하게 배제 배제 기준이 타당하면 보장됨 정답을 유지하면서 방문 상태 수 감소
탐욕 전략 현재 단계에서 가장 좋아 보이는 선택 수행 일반적으로 보장되지 않음 큰 수부터 선택하는 방식은 일부 정답을 놓칠 수 있음

5. 수행 과제

  1. 상태 공간을 선택·미선택의 이진 트리로 설명한다.
  2. 완전 탐색 함수와 가지치기 함수의 동작을 분석한다.
  3. 두 가지 가지치기 기준이 안전한 이유를 설명한다.
  4. 정답 부분집합과 방문 상태 수를 출력한다.
  5. 가지치기 전후의 방문 상태 감소율을 계산한다.
  6. 탐욕 전략이 항상 정답을 보장하지 않는 이유를 반례와 함께 설명한다.

7. 정답 포함 전체 코드

numbers = [3, 7, 11, 14, 18, 21]
target = 32

solutions: list[list[int]] = []
visited_pruned = 0
visited_full = 0

# 뒤에서부터 남은 합을 빠르게 계산하기 위한 배열
suffix_sum = [0] * (len(numbers) + 1)

for i in range(len(numbers) - 1, -1, -1):
    suffix_sum[i] = suffix_sum[i + 1] + numbers[i]


def search_pruned(
    index: int,
    current_sum: int,
    selected: list[int],
) -> None:
    """
    가지치기를 적용하여 목표 합을 만드는 부분집합을 탐색한다.
    """
    global visited_pruned
    visited_pruned += 1

    # 목표 합을 찾은 경우
    if current_sum == target:
        solutions.append(selected.copy())
        return

    # 모든 수를 확인한 경우
    if index == len(numbers):
        return

    # 가지치기 1:
    # 모든 수가 양수이므로 현재 합이 목표를 넘으면 더 탐색할 필요가 없다.
    if current_sum > target:
        return

    # 가지치기 2:
    # 남은 수를 모두 더해도 목표에 도달하지 못하면 더 탐색할 필요가 없다.
    if current_sum + suffix_sum[index] < target:
        return

    # 현재 수 선택
    selected.append(numbers[index])
    search_pruned(
        index + 1,
        current_sum + numbers[index],
        selected,
    )
    selected.pop()

    # 현재 수 미선택
    search_pruned(
        index + 1,
        current_sum,
        selected,
    )


def search_full(
    index: int,
    current_sum: int,
) -> None:
    """
    가지치기를 하지 않고 모든 선택·미선택 상태를 탐색한다.
    """
    global visited_full
    visited_full += 1

    if index == len(numbers):
        return

    # 현재 수 선택
    search_full(
        index + 1,
        current_sum + numbers[index],
    )

    # 현재 수 미선택
    search_full(
        index + 1,
        current_sum,
    )


search_pruned(0, 0, [])
search_full(0, 0)

# 중복 제거 후 정렬
unique_solutions = sorted(
    {tuple(item) for item in solutions}
)

reduction_rate = (
    1 - visited_pruned / visited_full
) * 100

print("=" * 54)
print("정답 부분집합")
print("=" * 54)

for item in unique_solutions:
    print(list(item))

print("\n가지치기 방문 상태 수:", visited_pruned)
print("완전 탐색 방문 상태 수:", visited_full)
print("감소율:", f"{reduction_rate:.1f}%")

10. 예시 정답

문항 1 정답
상태는 현재 확인 중인 인덱스, 현재 합, 선택한 수 목록이다. 초기 상태는 인덱스 0, 합 0, 빈 선택 목록이며 목표 상태는 현재 합이 32인 상태이다. 각 단계에서 현재 수를 선택하거나 선택하지 않고 다음 인덱스로 이동한다.
문항 2 정답
모든 수가 양수이므로 현재 합이 32를 넘으면 이후 어떤 수를 추가하더라도 합은 더 커진다. 따라서 목표 합으로 돌아올 수 없어 해당 상태 아래를 탐색할 필요가 없다.
문항 3 정답
현재 합에 남은 모든 수를 더한 값이 32보다 작다면, 가능한 최대 합도 목표에 도달하지 못한다. 따라서 해당 분기는 정답을 포함할 수 없다.
문항 4 정답
가지치기는 정답이 존재할 가능성이 없는 상태만 배제한다. 배제 기준이 논리적으로 안전하다면 정답을 포함하는 상태는 제거되지 않으므로 완전 탐색과 같은 정답을 얻는다.
문항 5 정답
현재 가장 큰 수를 선택하는 것이 이후 전체 합을 정확히 32로 만드는 최선의 선택이라는 보장이 없다. 예를 들어 21을 먼저 선택하면 11을 더해 정답을 만들 수 있지만, 다른 입력에서는 큰 수 선택 때문에 작은 수들의 조합으로 이루어진 정답을 놓칠 수 있다. 탐욕 전략은 탐욕 선택 속성이 성립하는 문제에서만 최적해를 보장한다.

12. 종합 정리

완전 탐색: 모든 상태를 확인하므로 정확하지만 상태 수가 지수적으로 증가할 수 있다.

가지치기: 정답 가능성이 없는 상태를 안전하게 제거하여 탐색량을 줄인다.

탐욕 전략: 현재의 최선 선택만 수행하므로 빠를 수 있지만 문제에 따라 정답을 보장하지 않는다.

적용 조건: 가지치기 기준은 입력 자료의 성질을 근거로 정당화해야 한다. 이 코드의 첫 번째 기준은 모든 수가 양수일 때만 안전하다.
